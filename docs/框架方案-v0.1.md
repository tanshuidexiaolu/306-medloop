## 0. 三分钟读完

**一句话**：把 306 的 203 个考点做成一张会自己衰减的"掌握度地图"，每天只推你该练的题，练完自动算出你当前能考多少分。

**三个关键设计选择**

| 选择 | 我的建议 | 理由 | 代价 |
|---|---|---|---|
| 个性化靠什么 | 掌握度 + 记忆稳定性**双参数**，不是对错率 | 对错率分不清"不会"和"忘了"，双参数能分别处理 | 需要连续用 3~5 天才收敛 |
| 每天练什么 | **系统生成**计划，你只微调 | 备考最大的隐性浪费是每天决定"练什么" | 前 1 周计划可能不准，需要校正 |
| 技术形态 | 纯静态网页，双击即开，数据存本机 | 零安装、零成本、隐私不出本机、你随时能看 | 不能多设备同步；换设备要手动导出 |

**需求已确认**（本轮）：

- 功能重心：题海+错题本+遗忘曲线 / 每日计划+督学 / 全真模考+分数预测 / 知识图谱+薄弱诊断 → **四项全要**，按 §9 分期
- 题库来源：**我按考纲与教材生成考点级题目，你审核**

**待你拍板**：§12 共 8 项，其中 5 项影响 P1 开工（考试日期、目标分、每日时长、各科自评、是否手机优先）。

## 1. 产品定义

### 1.1 三类使用场景

| 场景 | 时长 | 需要什么设计支撑 |
|---|---|---|
| 碎片时间（通勤/课间/排队） | 5–15 min | 手机可用、单次 5~15 题的短会话、随时中断不丢进度 |
| 每日固定复习 | 1–2.5 h | 自动计划块、进度条、连续天数（督学） |
| 周度检验 | 2–3 h | 全真模考、结构化报告、与上次模考对比 |

### 1.2 它解决什么

1. **不知道练什么** → 每天打开就是一份排好序的任务清单，带"为什么安排这个"的解释
2. **刷完就忘** → 每个考点记记忆稳定性，到期自动回流，不靠你自觉复习
3. **不知道自己什么水平** → 每答一题更新掌握度，随时给出 300 分制预测分与区间
4. **错题反复错** → 错题本 + 错误次数 + 关联考点，重做时优先抽同考点的变式
5. **基础学科放弃过早** → 按考纲分值权重分配时间，避免"凭感觉偏科"

### 1.3 明确不做（范围边界）

- ❌ 不做社交、排名、自习室、打卡朋友圈——分散注意力，且不是个性化
- ❌ 不碰政治/英语——只服务 306 单科
- ❌ 不做押题、预测题、内部消息——只做考点覆盖与记忆管理
- ❌ 不替代教材和视频课——定位是"练"，不是"学"；遇到不会的考点会引导你回教材章节
- ❌ 不保存或分发真题原文（版权由导入方负责，见 §7.6）

## 3. 核心流程

**首次进入（一次性，约 25 分钟）**

```
选择目标（考试日期/目标分/每日时长/六科自评）
        ↓
能力诊断卷（24 题，6 科各 4 题，覆盖各难度）
        ↓
生成初始掌握度画像 → 生成第一份 7 天计划
```

**每日循环（约 150 分钟）**

```
打开今日页 → 看到 3 个计划块（附"为什么这样安排"）
   ↓ 逐块进入答题
答题 → 每题即时判定 + 更新掌握度/记忆稳定性
   ↓
会话结束报告（正确率/用时/涉及考点/错题）
   ↓
夜间自动重算：明天哪些考点到期、哪些章节最该补
```

**模考循环（每周 1 次）**

```
选择迷你(30题/45min) 或 全真(165题/180min)
   ↓ 答题中不显示答案，可用答题卡跳转
交卷 → 按题型计分 → 折算 300 分制 → 学科/题型分解 → 错题入库
   ↓
与上次模考对比 → 更新全科掌握度 → 调整下周计划权重
```

### 4.2 三条架构约束（避免以后改乱）

1. **视图不写算法**：页面只调用 `engine.js` 暴露的函数；换页面不影响模型。
2. **状态单向**：所有写入集中在 `engine.applyAnswer / store.save`，便于日后换成后端接口。
3. **题库只认考点名**：新题目只写 `subject/chapter/kp` 三个中文名，由 `bank.js` 解析挂载；找不到考点会被丢弃并报错，不会污染图谱。

## 6. 算法设计

### 6.1 掌握度更新

```
答对： m ← m + 0.22 · (1−m) · (0.7 + 0.6d)
答错： m ← m − 0.30 · m · (0.5 + 0.8(1−d))
```
d 为题难度。效果：做对难题涨得多，做错简单题掉得多；m 有上下限（0.02~0.99），不会一次题就满分或归零。

### 6.2 记忆保持率与复习调度

```
R = exp(−Δt / S)            S：记忆稳定性（天），每答对一次 S ×(1.7+0.35d)，答错 S ×0.5
R < 0.78  → 进入"待复习"队列
```
含义：同一个考点，第一次答对约 2 天后再问就不稳；连续答对 4 次后可撑 2~3 周。**复习队列不是按对错排序，而是按"遗忘风险"排序**——这是本产品最核心的差异化。

### 6.3 出题优先级

```
优先级 = [0.45·(1−m) + 0.35·(1−R) + 0.15·错率 + 0.05·久未练] × (0.55 + 1.5×学科权重)
```
再对"刚好不会"的题加权：预测答对概率 p = sigmoid((m − d)·7 + 0.35)，取 p≈0.65 的题最优先；5 天内做过的题降权。

### 6.4 每日计划生成

按每日可用时长切三块：

| 块 | 占比 | 内容 | 目的 |
|---|---|---|---|
| 遗忘曲线复习 | 26% | 复习队列里 R 最低的考点 | 防遗忘，最高性价比 |
| 短板突破 | 40% | 掌握度最低的 2~3 个章节 | 补结构性缺口 |
| 跨章综合 | 34% | 按学科权重抽 A2/X 型题 | 练临床思维与多选完整度 |

每块都给出"为什么安排"的一句话解释，避免变成黑箱。

### 6.5 分数预测

```
学科预测分 = 学科满分 × (0.16 + 0.84 × 掌握度) × 覆盖率修正
总分 = Σ 学科预测分，展示为 区间 ±15
```
覆盖率修正：学过考点越少，越向"基础自评"先验回归，防止只做 10 题就报 280 分。

### 6.6 冷启动与边界

| 情况 | 处理 |
|---|---|
| 全新用户 | 用六科基础自评 初始化先验掌握度；首次诊断卷校正 |

## 8. 技术选型与取舍

**选：纯静态（HTML + CSS + 原生 JS，无构建、无依赖、localStorage）**

理由：框架阶段你要能直接打开看；零安装成本；数据只在本地，隐私风险最低；单文件部署（拷走整个文件夹即可）。

**不选 React/Vite 的原因**：多一层构建与依赖，对"先看框架"是负担；等真的需要多端或云同步再迁，届时 `engine.js` 可原样复用（它不依赖任何框架）。

**已知局限与对策**

| 局限 | 影响 | 对策 |
|---|---|---|
| 不能多设备同步 | 手机/电脑数据分离 | 导出/导入 JSON；P4 再做云同步 |
| 数据可能被浏览器清掉 | 学习记录丢失 | 每周提醒导出备份（P1 做） |
| `file://` 下 localStorage 可能被禁 | 无法保存 | 已内置降级：内存模式 + 明确提示 |
| 165 题全真模考需 ≥200 题 | 题库不足开不了 | 组卷时明确报缺口；P3 补齐 |
| 无后端，做不了账号体系 | 换设备/重装要手动搬 | 明确标注为单机工具 |
